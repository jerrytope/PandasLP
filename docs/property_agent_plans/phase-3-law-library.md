# Phase 3: Law library (Layer 2)

**Goal:** the agents can fetch the exact text of a law section when they need to quote or rely on it, instead of answering from memory or searching the web.

Search approach (decided): **exact lookup + Postgres keyword search** first. Vectors (pgvector) only if testing shows misses.

## Files
- `documents/law documents/manifest.json` (new)
- `scripts/law-ingest.mjs` (new) + `npm run laws:ingest`
- `add-law-library.sql` + copy in `supabase/migrations/`
- `lib/property/tools/lawLookup.ts` (new)

## Tasks

### Manifest
- [ ] `manifest.json`, one entry per law (1–59, minus any not obtained): `lawNo`, `title`, `file`, `jurisdictions` (states or "all"), `areas` (which sub-agents use it), `edition`, `sourceUrl`, `checkedBy`, `checkedAt`.
- [ ] Rules: Part B applies to the FCT, Anambra, Enugu, Cross River, and Lagos only where no Lagos law replaces it. Part E is per western state (each state's own file).

### Ingestion
- [ ] Extract text from each PDF; detect scanned pages (little or no text) and run OCR on them.
- [ ] Split by section (`Section 22`, `22.`, `s. 22`, plus Part/Schedule headings). Keep the heading and the section number.
- [ ] Quality report (`documents/law documents/ingest-report.md`): per law, the page count, OCR pages, sections found, and suspicious pages (too short, garbled characters).
- [ ] Load idempotently: re-running a law replaces its sections.
- [ ] Human spot-check of key sections: LUA s.22/s.26; Lagos Tenancy Law s.13; FCT Recovery of Premises Act ss.7–9; Wills Law signing formalities; PCL mortgage sections; CAMA signing of deeds.

### Tables
- [ ] `law_documents` (law_no PK, title, jurisdictions[], areas[], edition, file, checked_by, checked_at).
- [ ] `law_sections` (id, law_no FK, section, heading, text, jurisdictions[], areas[], `tsv tsvector` generated from heading + text, GIN index). Leave room for an `embedding vector` column later.
- [ ] Service role only. No browser access.

### Tools
- [ ] `get_section({ law, section })`: exact. `law` accepts the number or a known short name (e.g. "Land Use Act").
- [ ] `lookup_law({ query, limit })`: `websearch_to_tsquery` + `ts_rank`, filtered to the matter's state and area. Returns the law, section, heading and an excerpt (capped length, to control tokens).
- [ ] Citation rule enforced in the shared prompt, and checked in `emit_document`: any "section N of <law>" in a document must have been returned by a tool in this conversation; otherwise the document is rejected back to the agent.
- [ ] The Fair Market Value schedule (no. 38) is excluded from agent tools (internal only).

### Evaluation
- [ ] 10 real client-style questions per area. Record whether the right section was in the top 3 results. If misses keep happening, write it up and add vectors (separate task, needs an embeddings provider).

## Done when
- The Lagos, FCT and nationwide laws are loaded and spot-checked.
- The tools return correct sections for the evaluation set.
- A document citing an unfetched section is rejected.

## Progress notes (15 Oct 2026)

**What changed:** instead of PDFs, the legal team sent `docs/pandaslp-law-library-seed.sql` (generated by their `scripts/law-library/build.mjs`, which is not in this repo). It fills `law_documents` (15 laws: 6 with text, 9 `not_sourced`, each with a note saying why) and `law_sections` (239 sections, long ones split into chunks, each with a 384-number embedding). The plan is now three layers: (1) this library, (2) vector search over it once the embedding model is known, (3) web search for laws not in it, until the documents arrive.

**Step 1, built** (`npm test` 455 passed with no API calls; `npx tsc --noEmit` clean):
- `add-law-library.sql`: the two tables exactly as the seed expects, a keyword index, `search_law_sections(p_query, p_state, p_limit)` (an OR-query from the client's words, ranked; only `ingested` laws that apply in the state or in all states), RLS server-only, pgvector for the embedding column, and the `law_lookup` event kind. **Not yet run on Supabase.** Also copy it into `supabase/migrations/` (folder missing from this clone), then load the seed.
- `lib/property/lawLookup.ts` (pure): which law a reference means ("LUA", "Tenancy Law of Lagos State"), section numbers ("s.13(4)" becomes 13), the search words, and every "section N of the X Act/Law" in a text.
- `lib/property/lawLibrary.ts`: the `LawLibrary` interface and the Supabase version. `lib/dev/sqliteLawLibrary.ts`: the same on SQLite with full-text search, loaded straight from the seed file, used by the tests and the local harness.
- Tools `get_section` and `lookup_law` (`lib/property/tools/lawTools.ts`): filtered to the matter's state. A `not_sourced` law or another state's law is refused; the Lagos Tenancy Law is flagged as not applying in Ikoyi, VI, Apapa and Ikeja GRA. `lookup_law` also lists relevant laws whose text is not in yet.
- **Citation rule** in `emit_document`: a document may cite "section N of X" only if it was looked up for this matter (kept across turns as `law_lookup` events), is in the area's own rules or templates, or came from `prepare_consent_application`.
- Search checked on the real seed: "notice to quit yearly tenant" (Lagos) finds Tenancy Law s.13 first; "two years rent in advance" finds s.4; consent questions find Land Use Act ss.22 and 21. A Lagos law never comes back for another state.

**Found by the seed:** Tenancy Law of Lagos State s.13(4): notice to a quarterly, half-yearly or yearly tenant need not end on the anniversary of the tenancy. `calc_notice_to_quit` applied the anniversary rule in Lagos too; it no longer does (it still applies outside Lagos and in the Lagos excluded areas). **Lawyer to confirm.**

**Step 2, vector search (to do):** the seed's 384-number embeddings need the same model on the query side, and neither the model name nor the build script is known. It can be identified without the old repo: embed a few seed sections with the likely 384-dimension models (all-MiniLM-L6-v2, bge-small-en-v1.5, e5-small-v2, gte-small) on a laptop and see which reproduces the stored numbers. Then run that model in the server (no API cost) and combine its ranking with the keyword search.
